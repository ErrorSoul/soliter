# INDEX.md — навигационная карта (символ → файл)

Цель: прыгать в нужный файл/символ без чтения всего проекта. Номеров строк нет —
точную строку добирать `grep`'ом по имени символа. Архитектуру/z-index/респонсив см.
[architecture.md](./architecture.md). Этот файл — только «что где лежит».

## Раскладка

- **Оформление экранов:** `tools/build-theme.py --theme classic|jade|vivid` генерирует
  `gui/ui.gui`, `gui/theme.atlas`, `assets/ui/` и палитру `main/Scripts/theme.lua`.
  `ui.gui_script` сохраняет обработку переходов и локализацию; кнопка обучения
  на старте грузит учебную партию через `start_game` без очистки сохранения.
  `card.go` рисует отдельный контур на z=0.0002 относительно карты; лимит
  `sprite.max_count=256` включает 40 пятёрок «лицо/рисунок/тень/контур/подсветка» и слоты.
  Браузерный сценарий `menus` проходит старт → обучение → победа → меню → игру.
- **Нефритовая колода:** после `build-theme.py --theme jade` запустить
  `python3 tools/build-jade.py`. 32 изображения в `assets/jade/cards/`,
  кнопки в `assets/jade/buttons/`, исходные драконы в `assets/jade/emblems/`.
  Числа и символы мастей набраны векторно и целиком входят в верхние 35 px
  карты; имена atlas-анимаций и размеры 90×150 сохраняются.

- **Яркие звери:** `tools/build-theme.py --theme vivid` + `tools/build-vivid.py`.
  По уточнению владельца используются **исходные** лиса / орк / сова и три
  отдельных дракона из `assets/cards/`. SVG-раскладка сохраняет исходную
  рамку и помещает рисунок ниже верхних 35 px. В левом верхнем углу — квадрат
  цвета масти с крупным белым числом (у дракона — D). Только перекрытые карты
  при шаге колонки <32 px переключаются на `_compact` (индекс 18 px);
  открытая последняя карта всегда крупная. `tableau_script` отправляет
  `index_layout`, `card.script` переключает atlas-анимацию без изменения эффектов. Лотос со своей рамкой,
  рубашка, фон и кнопки сбора — исходные. `theme.wildlife=false` возвращает
  термин «драконы». Генерированные тигр/панда/сова больше не используются.
  Правила, формат сохранений, эффекты и музыка прежние.
- **Живые животные и слоты:** `build-vivid.py` собирает 108 кадров: 54 драконьих
  и 54 прозрачных для лисы/орка/совы. Обычные ранги используют общий `#portrait`
  поверх `_empty`-лица: номера и рамки неподвижны, кадры не дублируются для рангов.
  `dragon_motion.lua` задаёт редкий idle, hover и случайные циклы при удержании
  (0.7–3 с до первого, 2–6 с между циклами), с отдельным PRNG без влияния на сдачу.
  Закрытые/компактные/собранные карты не анимируются; drop и подсветка гасят цикл.
  `base_slot.occupy_slot` отключает движение через `index_layout.exposed=false`
  также для восстановленных карт основания. Browser `foundationstill` проверяет это.
  `cursor.script` отправляет `dragon_hover` животным и драконам, free_cell пересылает.
  `menu_motion.lua` двигает отдельные боковые линии и дымку стартового экрана,
  проигрывает кадры трём драконам; вне меню ничего не обновляет.
  Browser `livingcards` проверяет движение меню и удержание животных/дракона;
  `dragonlife` — hover и редкий idle. Tableau сохраняет исходные три головы,
  основания помечены «2 → 10».
- **Подсветка учебной карты:** отдельный спрайт `#hint` в `card.go`,
  SVG-ресурс `card_hint` из `build-theme.py`. `card.script` пульсирует золотой
  рамкой, сохраняет исходный цвет лица, гасит рамку при drag и смене подсказки;
  `show_card_hint` возвращает её после ошибочного хода. Browser `tutorialfree`
  проверяет цвет края, возврат после неверного drop и доигрывание обучения.
- **Кнопки интерфейса:** единый шаблон `button()` в `tools/build-theme.py`: стабильная
  область ввода → анимированный `_face` → иконка и подпись. Общий `main/Scripts/button.lua`
  обрабатывает press/release, отмену за границей и отключённые кнопки; `ui.gui_script`
  передаёт список доступных кнопок текущего экрана. Действие происходит на отпускании.
  Browser `buttons` проверяет визуальное нажатие, отмену и клик у края, включая touch.
- **Музыка:** `tools/compose-garden.py` → `assets/music/quiet-garden.ogg` + `score.json`.
  С 2026-11-06 мелодия на октаву ниже, мягкая атака и приглушённые обертоны.
  `main/Game Objects/music.go` в корневой коллекции → `music.script`: одна
  зацикленная дорожка, плавный вход/выход, пауза без потери позиции.
  `ui.gui_script` отправляет `music_state` после жеста, хранит выбор в отдельном
  файле `audio`; кнопка доступна на всех экранах. Browser `music` измеряет PCM
  через Web Audio, проверяет mute, reload, resume, restart; `test_music.lua`
  проверяет отсутствие дублированных голосов и реверс затухания.

- `main/` — игровой рантайм (логика, слоты, ввод). `gui/` — UI. `solver/` — pure-Lua солвер + тесты.
- Точка входа: `main/main.collection` → `game_manager.script` → грузит level proxy (`soliter.collection`).
- `soliter.collection` / `soliter1.collection` — идентичны; содержат слоты + `card_table` (в нём `main.script`, фабрики `card_factory`, `cursor_factory`). **Это единственный источник координат слотов** — скрипты читают их в рантайме через `go.get_position(slot_id)`, хардкода нет. Сетка (G6, по дизайну): центры колонок 65, 169, 273, 377, 481, 585, 689, 793; служебный ряд y=457 — свободные ячейки 1–3, цветок 4, кнопки драконов 5, foundation red/green/blue 6–8; правее x=868 идёт GUI-рельс с кнопками, туда поле заходить не должно (пин — `solver/tests/test_layout.lua`).
- **Cross-collection через polling** (proxy-коллекции не шлют msg наружу): `sfx.pending`, `tutorial_state.*_dirty`, `tutorial_state.show_victory` — опрашиваются в update'ах `main.script` / `cursor.script` / `ui.gui_script`.

## Message-passing (sender → id → receiver), сжато

- **Инициализация:** `main` → `set_cards/set_free_slots/set_base_slots/set_flower_slot/set_tableau_slots/set_dragon_buttons` → cursor; `main` → `update_stack` → tableau; `main` → `set_button` → dragon_button.
- **Ввод/драг:** cursor → `start_drag/drag_update/drop_success/drop_failed/can_move_card` → card; card → `valid_card/invalid_card` → cursor. **O1:** `z` карты в руке — константа: её ставит `start_drag` одним присваиванием (`p.z + config.Z_CARD_DRAGGING`), и ту же величину `drag_update` кладёт в цель, поэтому анимировать по `z` нечего. Разъедутся эти два места — подъём поедет внутри `position`, а `ui_fx.drag_lag` даёт РАЗНУЮ длительность на карту, и стопка рисуется наизнанку (замер: 40 кадров инверсии, сценарий `dragz`). Троп драга ДВЕ, и обе несут z карты: колонка (`original_position` = позиция карты) и ячейка (`slot_with_card`: смещение по x/y нулевое, по z — своё). **O1b:** прибавка относительная, а `hit_test` читает позицию живьём, поэтому перезахват БЕЗ посадки (ветка A2 в `on_input`; карта, ещё летящая назад после `drop_failed`) отдал бы курсору уже поднятую точку и подъём копился бы (замер: 0.33 → 0.46 → 0.60 → 0.74, при `far = 1` карта исчезает). Поэтому карта считает подъём от своей `drag_base_z` и на неё же возвращается, а x/y после возврата назначает ВЛАДЕЛЕЦ: card → `relayout {id}` → tableau/free_cell, из ПОСЛЕДНЕГО колбэка покачивания (раньше — гонка с записью позиции слотом).
- **Валидация дропа:** cursor → `set_cursor/check_slot/can_pick_card` → слоты; слот → `slot_valid/slot_invalid` → cursor; free_slot → `slot_with_card/update_free_slot` → cursor; base_slot → `base_slot_full` → cursor.
- **Дроп-результат:** card → `occupy_slot` → целевой слот; card → `remove_card` → слот-владелец.
- **Авто-полёт (tableau детектит верх):** tableau → `send_to_flower_slot/send_to_base_slot` → cursor; tableau → `send_counter_to_button` → dragon_button.
- **Дельта-зеркало tableau→main (auto-finish/snapshot):** tableau → `tableau_card_added/tableau_card_removed` → main (`main.tableau_stacks` всегда свежее; оценка `check_auto_finish` отложена на 2 кадра в `update`).
- **Драконы:** free_slot → `change_free_slots_button_counter` → dragon_button; cursor → `set_button_state/get_dragon_cards` → dragon_button; dragon_button → `dragons_collected` (через 1.5с) → main.
- **В main:** base_slot → `card_to_base` → main; cursor → `check_auto_finish/send_auto_finish_check` → main; free_cell → `free_cell_changed` → main (C4); flower_slot → `flower_collected` → main (C5); main → `auto_collect_dragons` → cursor (G2: дожать кнопки сбора за игрока); cursor → `auto_collect_none` → main (не горит ни одна кнопка) → main → `auto_move_dragon` → cursor (G7: сдвинуть верхнего дракона на пустую колонку) → `auto_collect_moved` → main.
- **Сбор драконов мимо кнопки (реплей):** main → `collect_done` → dragon_button (C6; `is_enable=false` + `check_state` — то же состояние, что после клика).
- **Уровень/UI:** ui → `start_game/restart_level/unload_level` → game_manager; game_manager ↔ proxy: `async_load/enable` → proxy, `proxy_loaded/proxy_unloaded` → game_manager.
- **Render:** main → `use_fixed_fit_projection` → `@render:`.

## Солвер (`solver/`) — pure Lua 5.4, без Defold

| Файл | Роль | API |
|---|---|---|
| `rules.lua` | Движок правил + DFS-солвер (IDDFS, транспозиции, node-budget) | `deal(seed)` `legal_moves(state)` `apply_move(state,move)` `is_win(state)` `can_auto_finish(state)` `auto_finish_sweeps(cols,cells,top)` `can_move_to_foundation_safe(card,top)` `forced_moves(state)` `solve(state,opts)` `state_hash(state)` (экспортирован ради `hint.lua`: канонический ключ должен быть один) |
| `bridge.lua` | Снапшот игры → состояние солвера (только game→solver) | `card(gc)` `from_game(snap)` |
| `hint.lua` | Подсказка туториала: BFS до цели «сбор драконов состоялся». НЕ `rules.solve` — у того цель «пустой стол», а туториальная раздача её физически не имеет (замер: `solve` → `unsolvable`). Дедуп — `rules.state_hash`. | `find(state,opts)` → `hint,status` (`found`/`won`/`stuck`/`timeout`); `kind(state,move)`; `DEFAULT_BUDGET` |
| `board_view.lua` | Рендер состояния в текст (без IO) | `card_str(card)` `render(state,info)` `describe(move)` |
| `run.lua` | CLI: solve диапазона сидов, golden-файлы, self-verify | вход: `lua solver/run.lua --seeds A..B [--budget N]`; пишет `solver/golden/<seed>.txt` |
| `watch.lua` | Терминальный аниматор разбора партии | вход: `lua solver/watch.lua [--seed N --delay S --budget N --no-color]`; ре-экспорт `card_str/render/describe` |
| `replay.lua` | Pure director: `plan(state, moves, go_map)` → список директив для in-game авто-реплея (stage 2b). Без Defold — полностью unit-тестируем. | `M.plan(state,moves,go_map)` `M.BLOCKED`; директивы используются `debug_replay` в `main.script` |

**Типы ходов** (`rules.legal_moves`): `to_foundation` `to_free_cell` `from_free_cell` `tableau_to_tableau` `multi_to_tableau` `dragon_collect` `flower_auto` (+ `to_empty_tableau` в apply).

- **Правила хода/стекинга** → `tableau_script.can_stack_cards`, `card.is_correct_card`, `base_slot.check_correct_cards` (и зеркало в `rules.legal_moves`).
- **Авто-финиш** → `main.script` (`can_auto_finish`/`find_next_auto_card`/`auto_finish_step`) + `rules.can_auto_finish`, который вызывает единственную копию симуляции `rules.auto_finish_sweeps` (её же зовёт и игра — O2).
- **Сбор драконов** → `dragon_button.script` + `free_cell.send_to_dragon_buttons` + `cursor` `get_dragon_cards`. Счётчик кнопки = ВЫСТАВЛЕННЫЕ драконы (верхушки + free cells), декремента нет; зеркало — `rules.compute_dragon_counter`. Припаркованные драконы тоже улетают в стопку, и **явно освобождать их ячейки не надо**: `card.script` на `drop_success` шлёт `remove_card` прежнему владельцу. Второй `remove_card` в ту же ячейку роняет игру (`check_dragon(nil)`) — пин-тесты в `test_game_scripts` (C2).
- **Авто-сбор драконов на победе** (G2/G4/G7) → main `begin_auto_collect` → cursor `auto_collect_dragons` (жмёт РОВНО ОДНУ горящую кнопку за вызов). Не горит ни одна → cursor `auto_collect_none` → main `dragon_relocation` выбирает верхушку самой высокой колонки и пустую колонку → cursor `auto_move_dragon` (fly_card_arc → `drop_success`, тот же путь, что и все автоотправки) → `auto_collect_moved` → main ждёт 4 кадра и заказывает следующий шаг. Сдвигать нечего/некуда → `auto_collect_give_up`: вернуть ввод и засчитать победу. Числа — `reviews/probe_dragon_unblock.lua`.
- **Победа** → `main.script` (`board_cleared` = 27 номиналов + пустые ячейки + 0 драконов + **цветок в слоте**; `declare_victory`; точки входа — `card_to_base`, `dragons_collected` и `flower_collected`) + `tutorial_state.show_victory` (UI poll). С солверным `rules.is_goal` совпадает **по следствию, не по формуле** (у того — пустой tableau + пустые ячейки, без foundation и цветка; см. `architecture.md`). Мест, где ставится WIN, **шесть**, и условия разные — полный список с обоснованием в `architecture.md` → «Победа». Главное: `auto_collect_give_up` намеренно слабее (27 номиналов + пустые ячейки, без чистого стола) — запасной выход G2a от софт-лока, см. блок L в `plans/review-fixes.md`; все шесть зовут `tutorial_state.request_victory()`, поэтому платформенный `stop` уходит с любой победы. Шестая (`flower_collected`, блок M2) — единственная, достижимая при `auto_collecting == false` и без `card_to_base`: гонка «цветок под последней собранной мастью» + реплейный хвост, где последней директивой идёт автоулёт цветка. Путь «цветок из свободной ячейки последним ходом» в этот список НЕ входит — доска недостижима, разбор в `architecture.md`.
- **Звук** → `sfx.lua` (+ poll `sfx.pending` в `main.script` update).
- **Туториал (v3)** → подсказка считается ОТ ДОСКИ: `main.refresh_tutorial_hint` (снапшот → `solver/hint.lua` → id объектов) → `tutorial_state.hint` → `cursor` подсвечивает, `ui.gui_script` пишет текст по `hint.kind`. Сценарного списка шагов больше нет; `plans/tutorial-v3.md`.
- **Текст/языки** → `i18n.lua`.

## Ревью и эффекты — 2026-10-31

- `gui.restart_level(preserve_save)` → `game_manager.restart_level`: TUTORIAL, SKIP и PLAY NOW после **учебной** победы передают `preserve_save=true`. RESTART на рельсе и PLAY AGAIN после обычной победы по-прежнему удаляют старую партию.
- `card.go#shadow`: силуэт рубашки, виден только при подъёме; `card.reset_card_fx` отменяет масштаб и tint-анимации. Вспышка больше не использует таймер.
- `cursor.fly_card_arc`: независимые x/y, ограниченная высота, отдельные z для драконов; flower_slot только фиксирует конечную позицию.
- `tools/browser-test.py`: новые `tutorialsave` (SKIP, победа обучения, reload, затухание конфетти) и `pickupfx` (тень и полный возврат). `--release` включает пиксельную проверку запуска; `--mobile` использует CDP touch в click_game/drag_game; `--browser-channel chrome` выбирает системный браузер.
- `tools/browser-review.py`: пакетный прогон с отдельными браузерами, логами, снимками и summary.json.
