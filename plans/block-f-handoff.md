## 1. Архитектурные решения (сохранять дословно)

**A6 — deferral + coalesce (принято раньше, блок A, уже в master).**
`remove_card`/`update_stack` ставят `self.pending_top_check = true`; `update()` вызывает
`last_card_to_slot` один раз за кадр по осевшей верхушке. Смысл не в «одном кадре», а в
КОАЛЕСИНГЕ: при переносе стопки все `remove_card` приходят одной пачкой в один флаш очереди,
и промежуточная верхушка (карта, которая сама в переносе) больше не угоняется вторым
`drop_success` в base slot.

**A6-довесок (блок F, НОВОЕ, в рабочем дереве).** `occupy_slot` тоже ставит `pending_top_check`.
Обоснование замерено: без этой строки двойка/цветок, положенные из free cell на пустую колонку,
**не улетают автоматически** — на колонку приходит только `occupy_slot`, без `remove_card`/
`update_stack`, поэтому проверка верхушки не запускалась. Строку **оставляем** (см. TODO-1 —
чинить надо в другом месте).

**B0 — дельта-зеркало tableau→main (блок B, в master).** `tableau_script.self.stack` — единственный
источник правды по колонкам; tableau шлёт main два крошечных сообщения `tableau_card_added`/
`tableau_card_removed`, main зеркалит их в `self.tableau_stacks[index].cards`. Полные стеки НЕ шлём
(лимит Defold-сообщения ~2КБ, колонка растёт до 14+ карт); порядок FIFO гарантирован.

**F3 — решение про `screen_to_world`.** Функция сведена к явному тождеству. Поведение **не менялось**:
старый код алгебраически уже был тождеством (`w = w/(w/W) ≡ W` ⇒ `zoom ≡ 1`, `offset ≡ 0` ⇒
`world_x ≡ x`). Вопрос «нужен ли настоящий unproject на не-16:9 канвасе» **остаётся открытым** —
см. TODO-3.

**F10 — sticky-флаг вместо импульса.** `tutorial_state.show_victory` — импульс, который UI съедает;
`block_play_input` — липкий флаг, снимается только в `M.reset()` и в `main.script init`. Перезапуск
уровня всегда идёт через перезагрузку proxy ⇒ «вечной заморозки» не возникает (проверено по всем
4 вызовам `reset()` в `ui.gui_script` + `init`).

elseif message_id == hash("send_counter_to_button") then

      if c.id == message.id then return end   -- уже посчитан: выходим ДО counter/insert/check_state

## 9. Факты, которые легко потерять при компакте

**`card.id` ≠ `card.data.id` — это ловушка, которая чуть не породила второй блокер.**
`create_deck` (`main.script:89`) выдаёт всем четырём драконам масти **один и тот же** id колоды:
`{id = "d_red", value = 'd', suit = 'red', is_dragon = true}`. Уникален не он, а GO-идентификатор
из `factory.create`, который кладётся в запись карты отдельным полем
(`main.script:150`: `{ id = card, data = card_data, slot_id = slot_id }`).

Отсюда: **дедуп драконов обязан ключиться на `message.id` (GO), а не на `message.data.id`.**
Ключ по `data.id` проглотил бы драконов 2-4, `counter` никогда не дошёл бы до 4 и кнопка не
зажглась бы вовсе — точная инверсия починенного бага. Закреплено тестом «A6 dedup keys on the GO
id, so 4 distinct dragons still reach counter 4»; проверено мутацией (подмена на `data.id` роняет тест).

**Почему строку `pending_top_check` в `occupy_slot` нельзя просто удалить.** Замерено
(`a6_sim.lua`, сценарий S2): на master двойка и цветок, положенные из free cell на пустую колонку,
**не улетают** — на колонку приходит только `occupy_slot`, без `remove_card`/`update_stack`,
поэтому проверка верхушки не запускалась. Строка чинит это; двойной счёт драконов лечится
в `dragon_button`, а не откатом строки.

**Разная сила доказательств по пунктам блока F.** Замерены симуляциями на настоящих скриптах:
**F2, A6, F10** (+ дедуп). Проверены чтением кода и solver-замерами: **F1, F5, F6, F7, F9, C3**.
Не проверено вообще: поведение в браузере на не-16:9 канвасе (F3) и весь play-test.

**Гейт советников.** Прогон грока по блоку F состоялся по-настоящему: `grok-4.6` и `grok-4.5`,
обе `stopReason: end_turn`, обе независимо назвали блокер A6. Оговорка: обе запускали мои
симуляции из `reviews/repro/`, так что по A6/F2 это подтверждение моим же инструментом.
Исторически гейт по блокам A и B (`plans/launch-handoff.md §8`, «3 советника ✅») **не выполнялся** —
`grok-build` был мёртвым id, `.out` нулевые. Ловушка описана в скилле `grok-review`.
