## 1. Авто-сбор затирает `pending_drop` игрока → падение на `slot_valid` — `cursor.script:476-478` / `:371-373` — **блокер**

**ЧТО НЕ ТАК**  
`auto_collect_dragons` не глушит ввод и через `timer.delay` пишет в `self.pending_drop` тот же слот, которым пользуется обычный дроп. Если таймер срабатывает, пока игрок ждёт ответ слота, структура `{ slot = ... }` становится `{ slot_id, color }`, и обработчик `slot_valid` делает `self.pending_drop.slot.slot_id` → обращение к `nil`.

**КАК ВОСПРОИЗВЕСТИ**  
1. Дойти до `foundation = 27` при **двух** горящих кнопках драконов (две масти открыты, есть свободная ячейка).  
2. Авто-сбор ставит нажатия на `t=0` и `t=1.7`.  
3. После посадки первой масти (`flying_count` снова 0, ~1.0 с) схватить карту оставшейся масти и отпустить на валидный слот так, чтобы ушёл `check_slot`, а `slot_valid` ещё не обработан.  
4. В ~1.7 с срабатывает второй таймер авто-сбора.

**ПОЧЕМУ ЭТО НЕ ЛОЖНАЯ ТРЕВОГА**  
Зонд на реальном `cursor.script`: после `auto_collect_dragons` + `timer.flush()` поверх игрокового `pending_drop = { slot = ... }` вызов `slot_valid` даёт:

`attempt to index a nil value (field 'slot')` на строке 373.

`start_auto_finish` шлёт `disable_input`, авто-сбор — нет. Окна между мастями (после `flying_count→0` и до следующего таймера) достаточно для обычного хода.

## 2. `auto_collect_none` снова объявляет победу поверх живых драконов — `main.script:1108-1117` — **блокер**

**ЧТО НЕ ТАК**  
Заявленное условие победы — `board_cleared` (пустой стол). Запасной путь это обходит: нет горящих кнопок → `auto_collect_none` → `declare_victory` при `base_cards_count >= 27`, **без** проверки драконов. Это тот же класс бага, который блок якобы чинит («Victory поверх драконов»), только теперь он включён сознательно.

**КАК ВОСПРОИЗВЕСТИ**  
1. Раздача вроде seed **2 / 21 / 23 / 57** из `reviews/probe_win27.lua`: на `foundation=27` открыто &lt; 4 драконов масти, ни одна кнопка не горит.  
2. Доложить последнюю числовую карту в foundation.  
3. `card_to_base` → `auto_collect_dragons` → `pressed==0` → `auto_collect_none` → оверлей победы, драконы остаются на столе, `block_play_input` режет доигрывание.

**ПОЧЕМУ ЭТО НЕ ЛОЖНАЯ ТРЕВОГА**  
Код: `declare_victory` без `board_cleared`. Прогон зонда: *«4 партий, где не горит НИ ОДНА кнопка»*, вывод *«игра объявит победу, пока драконы ещё на столе»*. Тест `WIN27 собирать нечем — победа всё равно объявляется` **закрепляет регрессию как желаемое поведение**, а не ловит её.

## 3. Победа глотает `released` при активном драге; `update` продолжает таскать карту — `cursor.script:47-48` / `:631` + `declare_victory` — **серьёзно**

**ЧТО НЕ ТАК**  
После победы `tutorial_state.is_play_input_blocked()` отсекает весь `on_input`, в том числе `released`. Флаг `is_dragging` не сбрасывается. Ветка драга в `update(dt)` этот блок **не проверяет** и продолжает слать `drag_update`.

**КАК ВОСПРОИЗВЕСТИ**  
1. Авто-сбор жмёт кнопку; дуга ~0.7–1.0 с, `dragons_collected` через 1.5 с.  
2. В окне ~1.0–1.5 с (полёт закончился, `flying_count==0`, победы ещё нет) начать тащить любую оставшуюся карту.  
3. В 1.5 с приходит `dragons_collected` → при пустом столе `declare_victory` → `block_play_input`.  
4. Отпускание мыши/пальца игнорируется; карта едет за курсором под оверлеем до рестарта.

**ПОЧЕМУ ЭТО НЕ ЛОЖНАЯ ТРЕВОГА**  
Гард только в `on_input`; `update` смотрит лишь `is_dragging`. Авто-сбор делает окно 1.5 с обязательным путём, а не ручным кликом. Тот же класс дыры уже воспроизводился в `reviews/repro/f10_sim.lua`; новый код его расширяет.

## 4. `dragons_left` читает не ту форму зеркала; тест это маскирует — `main.script:939-940` / тест ~строка 1108 — **серьёзно**

**ЧТО НЕ ТАК**  
`free_cell.script` зеркалит `{ id, data = { value, suit, ... } }` (`card = self.card_data`). `snapshot_and_go_map` правильно читает `rec.data.value`. Новый `dragons_left` для ячеек делает `fc.card.value == "d"` — на живом зеркале всегда ложь. Тест «дракон в ячейке НЕ запечатан» кладёт **плоскую** `{ value="d", suit="red" }`, которой игра не пишет.

**КАК ВОСПРОИЗВЕСТИ (проверка утверждения автора)**  
1. В коде: припарковать дракона в free cell → `free_cell_changed` с вложенным `data`.  
2. Вызвать `dragons_left`: вклад ячейки = 0.  
3. Тот же state в форме теста → вклад = 1.

**ПОЧЕМУ ЭТО НЕ ЛОЖНАЯ ТРЕВОГА**  
Lua-зонд: real mirror → `dragons_left=0`, test shape → `1`. Сейчас ложную победу через `board_cleared` часто маскирует `live_cells` (там достаточно факта `fc.card`). Но:
- комментарий к `dragons_left` врёт относительно кода;
- ветка retry в `dragons_collected` (`dragons_left(self) > 0`) опирается на сломанный счётчик;
- тест создаёт ложную уверенность и сам является дефектом тестового покрытия.

## 5. Тесты авто-сбора не бьют гонки и закрепляют плохой исход — `test_game_scripts.lua` — **серьёзно** (качество страховки)

**ЧТО НЕ ТАК**  
- `timer.flush()` в стабе сбрасывает **все** колбэки сразу, без задержек 0 / 1.7 — не ловит пересечение с ходом игрока и нехватку ячеек между мастями.  
- Нет теста на сохранение/`disable_input` на время авто-сбора.  
- `WIN27 собирать нечем — победа всё равно объявляется` делает PASS из обхода `board_cleared`.  
- FX-тесты бьют реальный `ui_fx.lua` — здесь претензий нет.

**КАК ВОСПРОИЗВЕСТИ**  
Сломать `pending_drop` в таймере авто-сбора или вернуть победу только через `board_cleared` при `auto_collect_none` — указанные WIN27-тесты останутся зелёными (для `auto_collect_none` наоборот покраснеют только если «исправить» продукт; сейчас они охраняют баг).

**ПОЧЕМУ ЭТО НЕ ЛОЖНАЯ ТРЕВОГА**  
`defold_stub.timer.delay` игнорирует время; `run_all` → 107/0 при живых дефектах 1–3. «107/107» не доказывает отсутствие этих дыр.
