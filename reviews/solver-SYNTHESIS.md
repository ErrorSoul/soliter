**#3 отклонён:** B5 + `free_cell.script:46-49` → free cell принимает ЛЮБУЮ карту (вкл. цветок); гард противоречил бы B5. Цветок авто-улетает в `apply_mandatory` ДО ветвления → в поиске никогда не на вершине → гард не меняет поведение. Идём в сторону composer + буквального кода.

**#5 пропущено:** текущий `is_goal` (tableau пуст + free cells пусты/blocked) ⟹ `is_win`; буквальный `is_win` сломал бы mini-deal (нет цветка). grok-build: as-is приемлемо. run.lua дополнительно перепроверяет полные раздачи через `is_win`.

**#8 (safe-foundation остаётся mandatory) — обоснование:** форсирование «безопасного» ухода в foundation НЕ теряет решений, потому что safe-предикат provably solution-preserving для правил этой игры. Единственный потребитель карты значения V в tableau — это карта V−1 другой масти; предикат срабатывает ТОЛЬКО когда foundation обеих других мастей уже ≥ V−1 (т.е. ни одной V−1 на tableau больше не нужна никакая V). Значит форс безопасен и лишь обрезает поиск, не занижая %. (Обоснование — через свойство предиката, НЕ через бюджет-кривую.)

**Честные числа (seeds 1..50, СТАРЫЙ deck — до фикса build_deck):** бюджет 15k → solved=18/50 (36%), proven-unsolvable=0; 60k → 27/50 (54%), **proven-unsolvable=3** (seeds 10/18/27). Прежние 48% завышены нелегальным dragon-shortcut'ом (снят #2). Рост с бюджетом доказывает: (а) канонизация #4 SOUND (иначе бóльший бюджет не вернул бы решения), (б) бóльшая часть timeout = ограничение бюджета, НЕ нерешаемость. Добавлен флаг `--budget N`. **ВАЖНО (исправление):** ранее ошибочно писал «0 proven-unsolvable на всех бюджетах» — это неверно; при большем бюджете поиск исчерпывает пространство на части досок. «proven-unsolvable» = нерешаемо **под консервативной моделью солвера** (строгий счётчик драконов), возможно решаемо в реальной игре.

**Числа — это ПОЛ, не истинная доля:** (1) timeout-доминирование при малом бюджете; (2) счётчик драконов в солвере строже игрового монотонного (см. SPEC §3.4) → возможен недоучёт. Истинная доля ≥54% и растёт; точное число — на tamagochi с большим бюджетом. Lua-PRNG ≠ Defold → метрика репрезентативна по распределению, не по конкретным in-game seeds.

## Финальные числа — большой прогон на tamagochi (lua5.3, 2026-06-22)

Запущено на homepc (4 ядра, nice-19+ionice — вторым приоритетом под матрицы). Тесты на 5.3: 25/25 PASS.

**Бюджет-лестница (фикс. 200 сидов, 4 ядра):**

| Бюджет | solved | timeout (НЕ доказано нереш.) | unsolvable (конс. модель) |
|---|---|---|---|
| 60k  | 49.0% | 47.0% | 4.0% |
| 300k | 64.0% | 24.5% | 11.5% |
| 600k | 69.0% | 19.0% | 12.0% |
| 1.2M | 72.5% | 13.5% | 14.0% |

**Широкий прогон (1000 сидов @ 600k):** solved **67.3%** (673), timeout 21.1% (211), unsolvable-конс. 11.6% (116). 95% ДИ solved ≈ ±2.9пп — согласуется с 200@600k (69%).

**Интерпретация (честно):**
- Кривая выходит на плато с убывающей отдачей: удвоение бюджета 600k→1.2M даёт лишь +3.5пп solved. Из вновь разрешённых timeout-досок ~64% → solved, ~36% → unsolvable. Экстраполяция асимптоты под конс. моделью: **solved ≈ 78–81%, unsolvable ≈ 18–19%.**
- Это **нижняя граница** истинной решаемости: (1) timeout = ограничение бюджета, НЕ нерешаемость; (2) счётчик драконов в солвере строже игрового **монотонного** (SPEC §3.4) → часть «unsolvable-конс.» на деле решаема в живой игре; (3) Lua-PRNG ≠ Defold → репрезентативно по распределению, не по конкретным in-game сидам.
- **Вывод для запуска:** доля решаемых раздач высока (≥67% доказуемо даже под пессимистичной моделью с конечным бюджетом, истинная — выше). Отдельный механизм гарантии решаемости / перегенерации раздач для релиза **не требуется**.
