## 4. Гонка `suspend()` / `resume()` в аудио-стороже — `html5/engine_template.html:165–179` — **серьёзно**

**ЧТО НЕ ТАК.**  
`state` становится `"suspended"` только после resolve промиса. Сценарий:

1. `hidden` → `apply()` зовёт `suspend()`, state ещё `"running"`;
2. быстрый `focus` → `muted=false`, state всё ещё `"running"` → `resume()` **не** зовётся;
3. `suspend` завершается → контекст навсегда `"suspended"` до следующего blur/focus.

Вызов `apply()` из конструктора (новье этого дифа) как раз попадает в окно загрузки, где focus/visibility дёргаются часто. `Promise.all(...).then(report, report)` реджекты не прячет, но гонку состояний не лечит. Бесконечного цикла логов нет; `webkitAudioContext` патчится тем же путём — ок.

**КАК ВОСПРОИЗВЕСТИ.** Во время создания AudioContext / первого suspend быстро вернуть фокус вкладке (DevTools или ручной alt-tab в момент старта). Звук молчит при видимой вкладке, пока не будет ещё одного blur→focus.

**ПОЧЕМУ НЕ ЛОЖНАЯ ТРЕВОГА.** Следует из Web Audio state machine и кода без очереди/токена поколения для in-flight ops.
