## Находки

### 1. Стенд не видит Lua-сторону `GameplayAPI.stop` — JS может игнорировать `gameplay(false)`, и всё останется зелёным

**Где:** `tools/browser-test.py:1020–1061` (части 3–5 `yasdk`); JS `html5/engine_template.html:357–360`; Lua `game_manager.script:63–68`, `gui/ui.gui_script:186`.

**Что не так.** `yasdk` доводит цепочку до `ready,start,stop,start` уходом вкладки в фон (`document.hidden`), не победой и не MENU. `stop` из Lua (`gameplay(false)`) стенд ни разу не вызывает. Юниты тоже JS не исполняют: `fake_html5` пишет в лог сам факт `html5.run("__ya.gameplay(false)")`, без моста.

Мутация, которая проходит **и юниты, и `yasdk`**:

```javascript
gameplay: function (on) {
    if (on) { wantGameplay = true; applyGameplay(); }  // false проглатывается
    return "";
}
```

Прогнал это в Node на вынутой логике моста: после «победы» вызовы остаются `ready,start`. Скрыть вкладку после этого всё равно даёт `stop` — именно поэтому часть 3 стенда мутацию не ловит.

**Как воспроизвести.** Подменить `__ya.gameplay` как выше. `/opt/homebrew/bin/lua solver/tests/run_all.lua` — зелёный (156/156). `yasdk` по сценарию — тоже: часть 3 шлёт `stop` через `visibilitychange`, не через Lua. В проде: победа и MENU не гасят геймплей для платформы, пока вкладка на переднем плане.

**Почему это не ложная тревога.** Пункт 1.19.3 требований Я.Игр: `stop` на прохождении уровня и на выходе в меню. Проводка в Lua есть, но единственный e2e-оракул платформенных вызовов эту ветку не смотрит. Скрыть вкладку — другой вход в тот же `applyGameplay`; он не доказывает, что `wantGameplay = !!on` жив.

Юнит «победа сообщает платформе» ловит удаление `msg.post(..., "gameplay_over")`. Юнит последовательности ловит удаление хендлера в `game_manager`. Оба не ловят поломку JS-стороны `false`.

## Что проверил, проблем не нашёл

**Порядок `LoadingAPI.ready` строго раньше первого `GameplayAPI.start`.** В JS `applyGameplay` выходит, пока `readySent` ложен; `loadingReady` ставит флаг и только потом зовёт `applyGameplay`. PLAY до ответа SDK: `wantGameplay=true`, `start` ждёт `loadingReady`. Это же заложено в `yasdk` (задержка 20 с) и подтверждено Node-симуляцией: `gameplay(true)` → `setReady` → вызовы пустые → `loadingReady` → `ready,start`.

**Парность start/stop на стороне намерений Lua.** `start_game` / `restart_level` / `switch_level` → `true`; `gameplay_over` / `unload_level` → `false`. Повторный `true` на рестарте внутри партии не дублирует `start` (`on === gameplayOn`). Победа шлёт `stop`, не дожидаясь MENU. Рестарт после победы снова `true`.

**`LoadingAPI.ready` один раз за жизнь страницы.** Владелец — `game_manager` в `main.collection` (id `ui`/`game_manager` на GO `main`), вне level proxy. `ya_settled` переживает выгрузку коллекции. `main.script` к SDK не ходит. JS-гард `readySent` дублирует это; сам по себе он юнитами не различается (Lua и так зовёт один раз) — это запасной слой, не дыра в проде.

**Деградация без SDK.** Нет `html5` / нет `__ya` / `absent` / `failed` / висящий `pending`: `pcall` вокруг `html5.run`, игра идёт, `language_ready` не шлётся, `ready`/`start` не уходят. `/sdk.js` 404 → `YaGames` нет → `init` помечает `absent`. Нет нужного feature — `feature()` возвращает `null`, вызова нет. Юниты на absent/pending/failed/меню без start — зелёные (перепрогнал).

**`start()` бросил.** В живом файле флаг ставится только после успеха; следующий `applyGameplay` (visibility / повторный `gameplay`) повторяет вызов. Node-симуляция: `ready,threw` → после скрыть/показать вкладку → `start`.

**Язык.** `i18n.detect()`: SDK → `?lang=` → система → `en`. Незнакомый код платформы падает вниз. `language_ready` вызывает `apply_language`, которая теперь перекрашивает и `STATIC_LABELS`, и хинт туториала, и тексты победы. Юнит «поздний язык перекрашивает и экран победы, и хинт туториала» это различает (без этой перекраски он красный). Поле `environment.i18n.lang` совпадает с документацией Яндекса (ISO 639-1).

**Гонки, которые смотрел.** PLAY до ответа SDK — см. выше. Вкладка в фон в момент загрузки уровня: `start` не уйдёт, пока `hidden`, по возврату уйдёт. Рестарт уровня не шлёт второй `ready` и не шлёт второй `start`. Победа: UI-пульс `show_victory` одноразовый, повторного `gameplay_over` нет (юнит). `game_manager` не умирает с прокси — состояние SDK не сбрасывается.

**D2 не сломан.** `overscroll-behavior`, `touch-action: none`, `context-menu-guard`, audio-сторож на месте; D1 добавлен отдельным тегом после них. Геймплей глушится только по `document.hidden`, звук ещё и по `!hasFocus` — так и задумано, негативный контроль в `yasdk` часть 5. Требование 1.3 (звук при потере фокуса) D1 не отменяет.

**Чего не гонял.** Сценарий `yasdk` в Chromium (нет свежего бандла). Песочницу Я.Игр — как и автор, локально нельзя. Не проверял, что живой `ysdk.environment.i18n.lang` всегда двухбуквенный ISO: мост берёт строку как есть, `two_letters` откусывает первые две буквы.

Если мержить только три коммита без рабочей копии — в них ещё живы смесь языков на победе/туториале (`apply_language` писала только `STATIC_LABELS`) и `gameplayOn = on` до `try`. В текущих файлах этого уже нет.
