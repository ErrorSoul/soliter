# Проверил и проблем не нашёл

**Зависание на ветке ожидания.**  
Цикл жив: `give_up` (wait) → `pending_collect_retry=4` → `update` тикает `auto_collect_wait` по `dt` и шлёт `auto_collect_dragons` → курсор → снова `auto_collect_none`. После 2 с — `end_auto_collect` → `enable_input`. `declare_victory` тоже снимает замок. «Ввод глухой, победы нет, никто не переспрашивает» по этой ветке нет.

Первый заход (`card_to_base` → нет кнопки) **не** шлёт `disable_input`; глушат `flying_count` на время дуги и `input_disabled` только если уже жали кнопку / двигали дракона. Это не зависон.

**Цветок в ячейке.**  
`last_card_to_slot` смотрит только tableau. `flower_collected` не придёт. Через 2 с — уступка при `base >= 27`. Хвост G2, не зависон.

**Рестарт / меню за время ожидания.**  
`unload`+`async_load` → новый `init`, новый `self`, новый курсор. `pending_collect_retry` и `auto_collect_wait` умирают со старым инстансом.

**`auto_collect_wait` между партиями.**  
Сброс в `begin_auto_collect`. Между партиями инстанс не переживает reload.

**Туториал / `debug_replaying`.**  
`begin_auto_collect` с этих путей не стартует; `dragon_relocation` при них выключен. Ветка wait для них недостижима.

**Тесты уступки (после 563cc6a).**  
Четыре теста: 0.7 с без победы; то же при `dt=0.008` (120 Гц); победа к 5 с; сразу, если цветок уже в слоте. Пара «полёт / вечность» ловит бюджет 0.53 с и бесконечное ожидание. Фикстура `win27_self.flower_collected = true` не возвращает старое правило «сдаваться поверх цветка на столе». Дыра тестов — только находка 1 (после посадки не моделируют зажигание кнопки).

**Зонд `settle` / `flower_auto`.**  
Только верхушки tableau; `apply_move(..., flower_auto)` снимает только `col[#col].is_flower`. Из ячейки и из середины колонки не улетает. Цифры 69/99/99/99 на 1..300 воспроизвёл. Зонд мгновенный — про тайминг кнопки он молчит, это не ошибка легальности ходов.

**`restartrace`.**  
`.values()`, `loads >= times` на быстрой очереди, `after != before`, клик 40 мс. Промах мимо кнопки → `loads == 0` → FAIL. Проглоченный клик → `loads < 8` → FAIL. Свойство «каждое нажатие дошло» этими оракулами закрыто. `show()` по-прежнему не ждёт `proxy_unloaded` — сценарий это не чинит и больше не притворяется, что чинит.

**`debugkeys` и R.**  
`s.expect(replay_spoke)` есть. Сломанный `debug_replay` на debug-сборке больше не зеленеет. Граница release (R молчит на неразрешимой в 40k раздаче; различитель — Space) записана честно.

**`engine_template.html` applying/again.**  
`hidden` → `suspend` in-flight → `focus` ставит `again` → после промиса повторный `apply()` с актуальным `muted`. Стек не растёт: при согласованном состоянии `ops` пустые и `now === muted`. `.then(done, done)` глотает reject. Несколько контекстов — один `map`. Потерянного «желаемого» состояния из-за снятого in-flight вызова не видно.
