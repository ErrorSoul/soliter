## 1. Бюджет ожидания цветка короче полёта — `main.script:1167–1173` + `cursor.script:353–357,562–574` + `flower_slot.script:14–19` — **блокер**

**ЧТО НЕ ТАК.**  
Правка уступки смотрит на `flower_collected`, а этот флаг ставится только в `flower_slot.occupy_slot`, то есть **после** `drop_success` в конце `fly_card_arc`. Полёт — `0.35 + 0.35 = 0.7` с (плюс кадр на `pending_top_check` в tableau).

Ожидание же считает **кадры**: `FLOWER_WAITS=8` × `pending_collect_retry=4` = **32** вызова `update`. Комментарий сам переводит это в «около полусекунды» — при 60 fps это **0.53 с < 0.7 с**. На 120 Hz ещё короче.

Сценарий из прошлого ревью («27-я карта лежала на цветке») по-прежнему закрывается победой **посреди полёта**: дракон под цветком ещё не верхушка (`remove_card` цветка тоже только на `drop_success`), кнопка не горит, уступка объявляет Victory. Та же дыра после `auto_collect_moved`: сдвиг открыл цветок → retry через 4 кадра → затем до 8 уступных ожиданий; суммарно ≈ 0.6 с, всё ещё меньше посадки.

Корень путаницы в комментарии: «улетит на следующем кадре» — на следующем кадре уходит лишь `send_to_flower_slot`, а не `flower_collected`.

**КАК ВОСПРОИЗВЕСТИ.**  
1. Доска: последняя десятка на цветке, под цветком — четвёртый дракон масти, остальные три открыты.  
2. Положить десятку в foundation → `begin_auto_collect` → нет кнопки → `auto_collect_none` → ветка ожидания.  
3. Через ~0.53 с (8×4 кадра) — оверлей победы; цветок ещё в дуге (~0.7 с), драконы на столе.  
4. Статика: сравнить `8*4/60` и `0.35+0.35` в `fly_card_arc`.

**ПОЧЕМУ НЕ ЛОЖНАЯ ТРЕВОГА.**  
Сигнал уступки завязан на `flower_collected` (`main.script:1170`, `flower_slot.script:19`). Полёт и снятие с колонки — только в callback дуги. Бюджет и длительность анимации читаются из кода напрямую; юнит-тесты длительность не моделируют (см. находку 2).

## 2. Пара тестов уступки зелёная при слишком коротком ожидании — `test_game_scripts.lua:1746–1790` — **серьёзно (тест)**

**ЧТО НЕ ТАК.**  
Заявлено: «ждём, пока цветок улетит сам» + «не ждём вечно». Фактически:

- первый тест проверяет один цикл `pending_collect_retry` → один `auto_collect_dragons` за 4 кадра, **без** `flower_collected` и без 0.7 с;
- второй крутит `auto_collect_none` до 20 раз, обнуляя `pending`, и ловит победу после `FLOWER_WAITS` — снова без полёта.

Оба остаются зелёными при любом `FLOWER_WAITS ≥ 1` и `retry ≥ 1`, в том числе при бюджете, который короче реальной анимации (находка 1). Пара отсекает «сдаться сразу» и «не сдаться никогда», но **не** свойство «дождаться посадки цветка».

Фикстура `win27_self` с `flower_collected = true` сама по себе правило «сдаваться поверх цветка» не закрепляет: старые WIN27-уступки проверяют доску **без** цветка; раннюю сдачу с цветком закрывают новые тесты — но слабо (см. выше).

**КАК ВОСПРОИЗВЕСТИ.**  
Оставить `FLOWER_WAITS=8` / retry=4 (или даже уменьшить бюджет, пока 8 ожиданий < 20). `lua solver/tests/run_all.lua` — оба новых теста PASS. В игре сценарий из находки 1 всё ещё ломается.

**ПОЧЕМУ НЕ ЛОЖНАЯ ТРЕВОГА.**  
В тестах нет `timer`/`fly_card_arc`/сообщения `flower_collected` перед финальной уступкой; только счётчик и один `update`-цикл.

## 3. `restartrace` не требует пересечения загрузок — `browser-test.py:645–675` — **средне (стенд)**

**ЧТО НЕ ТАК.**  
Прошлые дыры закрыты: `.values()`, `loads > 0`, `after != before`. Но оракул по-прежнему принимает **одну** успешную перезагрузку: `loads > 0`, не `loads >= 2` и не замер перекрытия. Восемь быстрых кликов повышают шанс гонки, но вердикт её не требует. Свойство «`unload`+`async_load` без `proxy_unloaded` безопасно» сценарий по-прежнему не доказывает — только «после серии кликов стол разложен и изменился».

Негатив «промахнуться мимо кнопки → 0 загрузок» да, ловится.

**КАК ВОСПРОИЗВЕСТИ.**  
Мысленная мутация: движок игнорирует клики, пока прокси занят, и обрабатывает только первый RESTART. `loads=1`, стол новый и полный → все `expect` зелёные, хотя перекрытия не было.

**ПОЧЕМУ НЕ ЛОЖНАЯ ТРЕВОГА.**  
В коде ожидания буквально `loads > 0`; `show()` всё ещё не ждёт `proxy_unloaded` (`game_manager.script:4–13`).

# Проверил и проблем не нашёл

**1. Зависание на ветке ожидания.**  
Цикл жив: `give_up` (wait) → `pending_collect_retry` → `update` → `auto_collect_dragons` → снова `auto_collect_none`. После `FLOWER_WAITS` вызывается `end_auto_collect` → `enable_input`. `declare_victory` тоже снимает замок. Вечного «ввод глухой, победы нет, никто не переспрашивает» по этой ветке нет.

**Цветок в ячейке.**  
`flower_collected` не придёт; после 8 ожиданий — уступка/победа при `base >= 27`. Это хвост G2, не зависон.

**Рестарт/меню за 32 кадра.**  
Новая партия = `unload`/`async_load` → новый `init` (новый `self`, курсор с фабрики). `pending_collect_retry` умирает со старым инстансом.

**`auto_collect_waits` между партиями.**  
Сброс в `begin_auto_collect`; между партиями инстанс не переживает reload. Утечки счётчика не видно.

**Туториал / `debug_replaying`.**  
`begin_auto_collect` с этих путей не стартует; `dragon_relocation` при `debug_replaying`/`tutorial_mode` отключён. Ветка give_up+wait для них по сути недостижима.

**3. Зонд `settle` / `flower_auto`.**  
Смотрит только верхушки tableau; `rules.apply_move(... flower_auto)` снимает только top-flower. Из ячейки и из середины колонки не «улетает». Цифры **69/99/99/99, уступок 0** на 1..300 воспроизвёл. (Оговорка: зонд мгновенный; он не моделирует 0.7 с — это усиливает находку 1, а не ошибку зонда в легальности ходов.)

**4. `debugkeys` и R.**  
`s.expect(replay_spoke, ...)` добавлен — сломанный R на debug-сборке больше не зеленеет молча. Граница release (R молчит на неразрешимой в 40k раздаче; различитель — Space) в сценарии записана честно; регрессии фикса не нашёл.

**5. `engine_template.html` applying/again.**  
Сценарий hidden→suspend (in-flight)→focus → `again` → повторный `apply()` с актуальным `muted` закрывает гонку из block I. Рекурсии нет: при согласованном состоянии `ops` пустые и `now === muted`. Оба аргумента `.then(done, done)` глотают reject. Несколько контекстов обходятся одним `map`. Потери «желаемого» состояния из-за снятого in-flight вызова не видно.
