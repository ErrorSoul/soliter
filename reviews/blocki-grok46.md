# Проверил и проблем не нашёл

**A. `debug_flags.lua`.** `M.enabled` считается один раз при `require` через `pcall(sys.get_engine_info)`. `shared_state = 1` — модуль один на все коллекции, повторная загрузка proxy его не пересоздаёт и не инвертирует. `pcall` закрывается в `false`: в релизе клавиши не всплывут из-за сбоя API; в debug стенд потеряет S/R/Space, в магазин это не утечёт. HTML5 `is_debug` — флаг варианта сборки, не порядка скриптов. Других клавиатурных входов в солвер/реплей нет: `debug_solve`/`debug_replay` ещё раз закрыты `DEBUG_SOLVER` в `main.on_message`; Space в курсоре и в `game_manager` оба на `debug_flags.enabled`. GUI RESTART/PLAY AGAIN — штатный путь игрока, не dev-клавиша. Биндинги S/R/Space в релизе остаются, обработчики молчат.

Безусловный `require("solver.*")`: bob и так кладёт модуль из-за статической строки. Кроме размера бандла и стоимости разбора при `init` коллекции побочных эффектов нет — модули чистые, игра на Lua 5.1 этот require уже возила, когда `DEBUG_SOLVER` был `true`.

**B. G3 в `can_auto_finish`.** Доигрывание, которое раньше доходило до победы, начинается только если `find_next_auto_card` уже находит верхушку. Если верхушка не та — раньше был `disable_input` на 0.5 с и выход на первом шаге без победы. Карта в ячейке по-прежнему не берётся (`find_next` смотрит только tableau); победа из `auto_finish_step` при живой ячейке уже закрыта зеркалом (`1187–1196`). Пустой tableau (`#remaining == 0`) и раньше не стартовал авто-финиш. Регрессии «партия, которая доигрывалась, теперь зависает» по коду нет.

**D. `engine_template.html`.** `function apply()` — декларация, всплывает в IIFE; вызов из конструктора после `new Orig()` видит готовый контекст. `webkitAudioContext` патчится тем же циклом. `Promise.all(...).then(report, report)` — реджект `suspend`/`resume` не бросает наружу и не крутит цикл (на `statechange` никто не подписан). `{{project.title}}`, `{{exe-name}}`, `{{display.width/height}}` — штатные токены Mustache Defold; в `game.project` нет `version`, `{{project.version}}` станет пустой строкой, сборку это не ломает.

**E. `audiobg` / `focus`.** `focus` теперь читает `states=`, вырезание `suspend`/`resume` его роняет. `audiobg` смотрит лог с `ctx>=1` после `add_init_script` на втором `goto` — убрать `apply()` из конструктора обычно значит пустой лог. Живой `AudioContext.state` в конце сценария никто не читает; для заявленной мутации «нет apply в конструкторе» этого хватает.

**F. Тесты G3 и `test_layout`.** Пара G3: выкинуть авто-финиш целиком роняет второй тест; убрать хвост `find_next` — первый. Оба сразу зелёными при мёртвом авто-финише не бывают. Они проверяют предикат, не проводку `pending_af_check` → `start_auto_finish` (один call site в `update`). Парсер `.gui` по скобкам; в `ui.gui` скобок в строках нет. Ростер слотов обязателен, пустой разбор больше не проходит. AABB по-прежнему `центр ± size/2` — это записанная граница метода, не регрессия этого дифа.

**G. Удаления.** `Game.script`, `gui/game.gui_script`, `gui/test.gui_script` ни в одной коллекции/`.gui` не подключены (`gui/` содержит только `ui.gui` → `ui.gui_script`). `apply_mandatory` был локальным и ниоткуда не вызывался; живой путь — `apply_mandatory_tracked` (`forced_moves` / IDDFS).
