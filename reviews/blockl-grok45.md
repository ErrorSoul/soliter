## Находки

### 1. Уступка по-прежнему объявляет победу над закопанным цветком и драконами при живом ходе в ячейку — `main.script:1205–1226`

**ЧТО НЕ ТАК.**  
`auto_collect_give_up` после исчерпания бюджета делает:

```lua
base_cards_count >= 27 and live_cells(self) == 0 → declare_victory
```

Без `flower_collected`, без `dragons_left == 0`, без проверки «есть ли ход в свободную ячейку».  
На синтетической доске `[flower, dragon]` + остальные колонки заняты драконами + ячейки пусты:

| проверка | результат |
|---|---|
| `dragon_relocation` | `nil` (нет пустой колонки) |
| `live_cells` | `0` |
| `board_cleared` | `false` |
| `rules.legal_moves` | есть `to_free_cell` с колонки цветка |
| `auto_collect_give_up` (wait исчерпан) | **`currentState = win`** |

То есть победа уходит при цветке и драконах на столе, хотя снять кроющего дракона в ячейку можно.

**КАК ВОСПРОИЗВЕСТИ.**  
Собрать доску: foundation=27, одна колонка `[f, d_*]`, остальные семь непусты, ни одна масть не открыта полностью (счётчики &lt; 4), free cells пусты. Дождаться `auto_collect_none` → уступка после `FLOWER_WAIT_SECONDS` (2.0). Юнит-эквивалент: тот же `self`, `auto_collect_wait = 99`, вызов `auto_collect_give_up`.

**ПОЧЕМУ НЕ ЛОЖНАЯ ТРЕВОГА.**  
Это прямо ломает заявленный дух G2a («ходов у игрока нет»). Ход есть: `to_free_cell`.  
Дифф **сознательно** не закрыл это: цветок в `give_up` не добавили, а тест `уступка не ждёт вечно: закопанный цветок не держит партию` **закрепляет** WIN при `flower_collected = false`.

**Про достижимость (честно):**

- На **солверных** траекториях сидов **1..500** в момент `foundation=27` форма «цветок закопан + 0 пустых колонок» **не встретилась** (7 раз цветок был закопан — всегда была пустая колонка → `dragon_relocation` спас бы).
- `probe_dragon_unblock` на 1..300: политика B доигрывает **99/99**, уступок **0** — но зонд перед политикой делает `settle()` = автоулёт **только верхушечного** цветка; закопанный цветок без пустой колонки этим замером не покрыт.
- После снятия номиналов с раздачи (грубый верхний оракул) форма «закопан + 0 пустых + кнопка не горит» есть в **129/2000** сидов (пример: seed 3, колонка `f,dg`).

Итого: на оптимальных солверных путях сценарий редкий/не виден; как **логика уступки** — дыра реальная и тестами охраняется. Для человеческого пути «последний номинал ушёл из ячейки, колонки не трогали» достижимость правдоподобна, но **явного сида + списка ходов я не построил**.

**По духу G2a:** нет. «Софт-лок вместо победы» здесь не аргумент: после `end_auto_collect` игрок как раз мог бы походить в ячейку, но `declare_victory` в том же вызове забирает стол.

## Что проверил и проблем не нашёл

### `board_cleared` + цветок — правка уместна
Старое условие на доске «только цветок в колонке, 27 номиналов, драконов 0» даёт `true`; с `flower_collected` — `false`. Подтверждено прямым прогоном предикатов. Ветка `card_to_base` уходит в `begin_auto_collect` вместо Victory на кадр раньше автоулёта — согласовано с кодом `tableau_script` (`pending_top_check` → следующий `update`).

### Победа не становится недостижимой из‑за `live_cells == 0`
- Цветок в незапечатанной ячейке: уступка **не** винтит, ввод возвращает (`enable_input`). Игрок может положить цветок в `flower_slot` (слот принимает `'f'`) и дальше собрать драконов → `dragons_collected` → `board_cleared`.
- «Все драконы уже собраны, цветок в ячейке, победы никогда» на полной раздаче не сходится: три масти занимают три ячейки, цветку негде лежать одновременно.
- Софт-лок «кнопки тухлые + нет пустых колонок + ячейки забиты + `live_cells > 0`» при полной переписи 12+1 математически тянет хотя бы одну горящую кнопку, либо оставляет ход «дракон из одиночной колонки в ячейку».

Регрессии вида «раньше выиграть можно было, теперь нет» на этих путях не видно. Наоборот, `live_cells` убирает ложный WIN при карте в ячейке.

### Пять точек WIN — рассинхрона, который ломает партию, нет
| # | место | условие | замечание |
|---|---|---|---|
| 1 | `card_to_base` | `board_cleared` | ок |
| 2 | `dragons_collected` | `board_cleared` | ок |
| 3 | `auto_collect_give_up` | 27 + `live_cells==0` | намеренно слабее (находка 1) |
| 4 | `auto_finish_step` | пустой tableau + нет живой ячейки | цветок на tableau не пройдёт; отдельный `flower_collected` не нужен |
| 5 | туториал / `dragons_collected` | `tutorial_mode` | отдельная мини-раздача |

Все пять зовут `tutorial_state.request_victory()`. `declare_victory` идемпотентен по `currentState == WIN`. Конфликта «одно место уже WIN, другое считает доску живой» с плохим хвостом не нашёл: повторный вход в победу — no-op.

Утверждение в доках/коммите «`board_cleared` == `rules.is_goal`» — **неточно**: `is_goal` смотрит только пустой tableau + нет живых ячеек; `is_win` — foundation + flower slot. На доигранной полной раздаче они сходятся *по следствию*, не по формуле.

### Гонки кадров / таймеры
- `FLOWER_WAIT_SECONDS = 2.0` > дуга `0.35+0.35 = 0.7`; бюджет в секундах (не в кадрах) — на 120 Hz не схлопывается.
- После `flower_collected` wait обнуляется, дальше `SETTLE_SECONDS = 0.3`; переспрос через `pending_collect_retry`.
- Обнуление на `auto_collect_moved` есть.
- Вечного «ввод глухой, победы нет, никто не переспрашивает» на ветке уступки нет: либо WIN, либо `end_auto_collect` + `enable_input`.

Юнит-тесты на ожидание моделируют `update`+`auto_collect_none`, не настоящий `fly_card_arc`; длительности зашиты числами. Для уже пойманных багов J/K этого достаточно; полёт как таковой тестами не исполняется.

### Зонд автора про «уступка никогда не стреляет»
На сидах 1..300 цифры **B = C = потолок = 99/99, give_ups = 0** воспроизвелись. Это поддерживает «на солверных хвостах G2a почти не нужен», но **не** оправдывает победу при закопанном цветке и свободной ячейке (находка 1).

## Вердикт

Блок L чинит две реальные дыры (`flower` в `board_cleared`, `live_cells` в уступке). Их стоит оставлять.

Сознательно сохранённый G2a по-прежнему сильнее правила «стол чист» и **слабее** собственного обоснования «ходов нет»: на доске `[flower, dragon]` без пустой колонки уступка винтит поверх цветка, хотя ячейка свободна. На солверных путях такую форму в выборке не поймал; логика и тесты её всё равно закрепляют.

Блокером мержа именно *этого* диффа я бы это не ставил, если продукт явно принимает «после 27 номиналов партия засчитана, даже с закопанным цветком». Если нет — дыра в уступке ещё открыта, и тесты её маскируют.
