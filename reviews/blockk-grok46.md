# Что проверил и не нашёл

### 1. Отложенные события → новый ход vs SETTLE 0.3 с

### 2. Зависание / затяжка / замок ввода

**Хвост уступки (ходов так и нет):**
- цветок не придёт (закопан / в ячейке) → максимум **2.0 с**, затем `end_auto_collect` → `enable_input`; при `base >= 27` ещё `declare_victory` (повторный `end_auto_collect` — no-op);
- цветок садится ~0.7 с → сброс → ещё 0.3 с → порядка **~1.0 с** до оверлея.

**Успешный авто-сбор.** Потолок `auto_collect_moves <= 24` × (0.7 с дуга + 4 кадра ≈ 0.07 с) + до трёх сборов по 1.5 с ≈ **≲ 23 с** в абсурде, если инвариант «каждый сдвиг уменьшает число закопанных» сломан. На живой доске закопанных ≤ 11 (12 драконов, верхушку не двигают при `#cards < 2`) → порядка **≲ 10 с** сдвигов + сборы. Это доигрывание, не зависон.

Цикл ожидания жив: `give_up` (wait) → `pending_collect_retry = 4` → `update` тикает wait по `dt` и шлёт `auto_collect_dragons` → курсор → снова `none`. «Ввод глухой, победы нет, никто не переспрашивает» по этой ветке нет.

**Кто снимает замок на каждом выходе:**

| Выход | Кто шлёт `enable_input` |
|---|---|
| Уступка (`give_up` дошёл до конца) | `end_auto_collect` (`:1114–1118`), затем `declare_victory` зовёт его ещё раз |
| Победа через `board_cleared` / `dragons_collected` | `declare_victory` → `end_auto_collect` |
| Цепочка кончилась, драконов больше нет, стол не пуст | `dragons_collected` → `end_auto_collect` (`:1415`) |
| Слот сдвига исчез (`auto_collect_none_final`) | снова `give_up` |
| Авто-финиш исчерпал верхушки | свой `enable_input` в `auto_finish_step` — на этой точке не стартует |

`begin_auto_collect` **сам ввод не глушит**. `input_disabled = true` ставит курсор только когда реально жмёт кнопку или запускает `auto_move_dragon`. На фазе ожидания цветка стол может оставаться кликабельным — это старое поведение G4, не регрессия SETTLE. `flying_count` закрывает пальцем только саму дугу (0.7 с).

Зависона «колбэк `fly_card_arc` не пришёл» этот диф не вводит и не лечит: без `auto_collect_moved` retry не ставится, wait тикает впустую, ввод так и остаётся глухим. Это поломка анимации, не уступки.

### 3. Таймер

Обнуления, которые есть в коде: `begin_auto_collect` (`:1110`), `flower_collected` (`:1365`), `auto_collect_moved` (`:1392`). Тик: `update` при `auto_collecting` (`:1452–1453`), и до посадки, и после.

| Событие | Что будет |
|---|---|
| `flower_collected` **до** `begin_auto_collect` (обычный случай: цветок улетел в середине партии) | Флаг true, wait=0 при выключенном сборе (тик молчит). `begin` снова ставит wait=0. Бюджет с первого отказа — SETTLE 0.3, не 2.0. Это нужно: дуги уже нет, ждать 2 с незачем |
| Дважды | Идемпотентно. `flower_slot.occupy_slot` **не** проверяет `empty` перед постом (`flower_slot.script:14–19`), второй `drop_success` теоретически сбросил бы wait ещё раз — лишние 0.3 с, не зависон. Второго цветка нет |
| Никогда (закопан / в ячейке) | `last_card_to_slot` смотрит только tableau. Через 2.0 с уступка при `base >= 27`. Хвост G2, не зависон |
| Игрок припарковал цветок в ячейку | Тот же «никогда». Если за 2 с авто-сбор **успевает** собрать всех драконов, выход другой: `dragons_collected` → `board_cleared` false (`live_cells > 0`) → `end_auto_collect` без победы. Это не уступка и не этот таймер |
| `auto_collecting = false` в момент `flower_collected` | wait пишется в 0 вхолостую. Следующий `begin` всё равно обнулит |

Комментарий у списка сбросов (`:1182–1187`) после `7a6432e` совпадает с кодом: «собранная масть» сама `wait=0` не пишет.

Lua-ловушка `flower_collected and SETTLE or FLOWER_WAIT` сработала бы при `SETTLE = 0` (`true and 0 or 2.0` → 2.0). Сейчас 0.3, ветка живая.

### 4. Тесты (`run_collect_frames` и четыре/пять таймерных)

`run_collect_frames` (`test_game_scripts.lua:1010–1024`) крутит `update(dt)` и на каждый новый `auto_collect_dragons` отвечает `auto_collect_none` — это тот же контур, что в игре, когда курсор не видит кнопку.

Что ловят:

- «уступка ждёт дольше полёта» + «не ждёт вечно» — пару «бюджет < 0.7 с» / «бесконечный wait»;
- `dt = 0.008` — кадровый бюджет (дыра круга J grok-4.5);
- посадка → 0.1 с ещё не win → затем win — `SETTLE = 0` и «не обнулять на посадке»;
- `auto_collect_moved` после 0.2 с → ещё 0.2 с не win — сброс на приземлении.

Мгновенную сдачу поверх цветка в дуге этими четырьмя зелёной не сделать. Старый тест «цветок сел — сдаёмся сразу» убран.

**Пять** старых тестов, которым добавили `run_collect_frames(1.0)` (G4 отказ ввода, WIN27 некуда сдвинуть, G7 одиночка, G7 бюджет, G7 победа снимает замок): это не подгонка утверждений. Уступка больше не мгновенная, а `auto_collect_none` в игре приходит только внутри уже начатого сбора — без `auto_collecting = true` wait в `update` не тикает, и тест мерил бы мёртвый путь. Их **исходные** оракулы (enable_input, win, нет `auto_move_dragon`) живы. Честно: **мгновенный give_up их по-прежнему зелёнит** (победа/enable случаются до цикла кадров, цикл сразу `break`). Задержку держат новые тесты, не эти пять.

Ограничение изоляции, не баг кода: харнесс **всегда** отвечает `none` и не моделирует `set_button_state`. Вентили времени сломать незаметно нельзя; проводку «после посадки кнопка реально зажглась и ход взяли» — можно. Это та же граница, что была в круге J.

Мелочь, не находка: `math.floor(0.7 / 0.016) = 43` кадра = **0.688 с**, не 0.7. Бюджет 0.69 с (всё ещё короче дуги) прошёл бы 0.7-секундный тест. При фактических 2.0 с это не дыра.
