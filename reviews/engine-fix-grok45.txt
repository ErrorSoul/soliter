Независимый ревью: сначала прочитаю дифф и скиллы ревью, затем сверю заявленные инварианты по реальному коду, а не по комментариям.Дифф на месте; читаю его целиком и параллельно разбираю затронутые исходники.Дальше сверю пути A2/`abort_drag` и то, откуда берётся `original_position` при повторном захвате.## Находки

### 1. `main/Scripts/card.script:105` + `cursor.script:106–130` — sticky elevation после A2 (рассуждение автора верно; O1 это не чинит)

`start_drag` делает `p.z + Z_CARD_DRAGGING` от **текущей** позиции. `hit_test` тоже читает `go.get_position` (`hit_test.lua:39–64`).

Путь A2 в одном `pressed`:

1. `abort_drag` ставит в очередь `drop_failed` на **старый** `original_position` (осевшая z).
2. В том же обработчике `hit_test` уже видит карту на поднятой z → новый `original_position` = elevated.
3. Потом приходит `start_drag` → ещё `+0.3`.
4. Void/`drop_failed` возвращает на **новый** `original_position` → карта **оседает на elevated z**.
5. `update_visible_cards` при void-дропе не зовётся → z не лечится.

Повтор того же A2 на той же карте накапливает baseline. У вас `far = 1` (`render.render_script:26–27`): от верхушки колонки (~0.03) примерно `0.03 + n·0.3` → к 4-му такому циклу z ≳ 1, карта уходит за far-plane.

**Про «до O1 было так же» — да.** До O1 `start_drag` z не трогал, но `drag_update` целил в `message.position + 0.3`, а `message.position` строился из того же elevated `original_position` из `hit_test`. Итог void-дропа тот же: settle на заражённый original. O1 лишь добавляет мгновенный `+0.3` в `start_drag`; механизм заражения baseline тот же.

**Воспроизведение:** HTML5, увести курсор с канваса без mouseup (карта остаётся в руке) → клик снова по этой же карте → отпустить в пустоту → повторить. Не путать со `stuck`/A2: там второй press идёт в **другую** колонку, заражения той же карты нет.

---

### 2. Тот же класс — mid-flight regrab после обычного `drop_failed` (автор честно ограничил инвариант; это не регрессия O1)

`is_dragging` уже false → `abort_drag` no-op. `hit_test` читает позицию в полёте назад → `start_drag` кладёт `+0.3` поверх недоехавшей z. Дальше как в п.1: void-дроп фиксирует заражённый original.

Лечится только абсолютной перекладкой: tableau `update_visible_cards` / free-cell `occupy_slot` с `slot_pos` (z≈0). Void-циклы не лечат.

### 3. `tools/browser-test.py` `scenario_regrab` — оракулы не сторожат накопление z и не сторожат O1-мерцание

Сценарий: три чистых press→drag→release в пустоту + пауза 700 мс. A2 и mid-flight не исполняются. После осевшего возврата каждый новый захват стартует с правильной z → равенство яркости зелёное даже при живом баге п.1–2.

Что реально ловит:

| Проверка | Ловит |
|---|---|
| `abs(b - base) < 20` | карту, не вернувшуюся (подложка 255 vs ~174) — да, чинит ложно-зелёный `expect_card_at` |
| `expect_empty_at(VOID)` | зависание на сукне в точке отпускания |
| `gain > 0.03` на зажатой карте | молча мёртвый tint |

**Ложный зелёный при сломанном коде:** вырезать подъём z в `start_drag` / вернуть анимацию z в `drag_update` — `regrab` останется зелёным (это зона `dragz`, не `regrab`). Оставить относительный `+Z` и ломать только A2 — тоже зелёный.

Порог тинта 3 % опирается на один замер «мутант +1.9 % от scale»; на тёмной карте/SwiftShader теоретически возможен дребезг. Это слабее, чем дыра по z выше.

Замечание по докстрингу `regrab`: история про краш в `drop_success` до `occupy_slot`, а сценарий бьёт в **void → `drop_failed`**. У `drop_failed` тоже был `sprite.set_constant` (до правки), так что негативный контроль с ERROR:SCRIPT правдоподобен, но цепочка в комментарии сформулирована неточно.

## Что проверил и проблем не нашёл

**Накопление z на других путях**

- Авто-финиш / `disable_input` → `abort_drag` → возврат на `original_position` захвата; при старте с осевшей доски не заражает.
- Сбор драконов: `abort_drag` (+ `except_id` для улетающей) — того же класса, не новый.
- Рестарт: proxy снимает GO — утечки z между раздачами нет.
- Потеря фокуса вкладки: отдельного abort нет; карта остаётся в руке, следующий press идёт в A2 (п.1). Отдельного пути накопления кроме A2/mid-flight нет.
- Free-cell тропа: `original_position = slot_pos` (z=0), void-возврат **лечит** z. Правка `drag_offset.z = go.get_position(...).z` согласована с `start_drag` (offset читается до доставки `start_drag`).

**Удалённый API движка**

- Живых вызовов `sprite.set_constant` / прочих из таблицы миграции 1.13 в `.script`/`.lua` нет (кроме комментария в стабе).
- Стаб намеренно не объявляет `sprite` — возврат старого API уронит юниты.

**`go.set("#sprite", "tint", …)`**

- Официальная замена в Defold 1.13 (`sprite.set_constant` → `go.set`).
- Карта на `/builtins/materials/sprite.material` — у материала есть `tint`.
- `play_animation` при `set_card` tint не обязан сбрасывать; на раздаче/рестарте GO новые. Поведения «set_constant работал, go.set молчит» для этого материала по докам не следует; `regrab` как раз сторожит наблюдаемый след.

**Мерж master (O2)**

- `scenario_o2sweep` / `scenario_celldrain` побайтово совпадают с master.
- Из `SCENARIOS` на ветке ничего master-ного не пропало; добавлены только `dragz` и `regrab`.
- O2-тесты в `test_game_scripts.lua` / `test_auto_finish_sweep.lua` на месте.
- `run_all.lua`: **198/198 pass** (счёт в INDEX на ветке сходится; на master INDEX всё ещё пишет 179 — это давняя протухшая цифра master, не потеря при склейке).

**O1 на осевшей доске**

- Арифметика «cursor composition + `Z_CARD_DRAGGING` = z после `start_drag`» в юнитах с прогоном через настоящий `cursor.script` выглядит согласованной для колонки и для ячейки.
- Заявленные «40 кадров инверсии» на движке в этом ревью **не перезамерял** (нужен бандл с `DEBUG_DRAG_PROBE` + `DEBUG_LONG_COLUMN`); по коду механизм инверсии до правки правдоподобен.

---

**Итог:** O1 для драга с осевшей доски выглядит сделанным правильно; замена tint/платформы — тоже. Единственная содержательная дыра, которую стоит чинить отдельно от «мерцания стопки»: относительный `p.z + Z` + `original_position` из живого `hit_test` оставляют достижимое накопление z через A2/mid-flight, а `regrab` это не ловит. Это не регрессия O1 (до правки baseline заражался так же), но и не «закрыто O1».
