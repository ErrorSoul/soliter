### 1. `DEBUG_SOLVER` и клавиши Space/S/R живы в релизном пути — `cursor.script:3,63–77`, `main.script:11`, `game_manager.script:43–46`, `input/game.input_binding:1–11` — блокер

**Как воспроизвести.** Собрать js-web, открыть в браузере (в том числе Я.Игры на десктопе): PLAY, затем `S` — солвер считает текущую раздачу; `R` — реплей гоняет настоящие карты; `Space` — `game_manager` шлёт `restart_level`, курсор параллельно делает `toggle_physics_debug`. На телефоне клавиатуры нет, на десктопной модерации — есть.

**Почему не ложная тревога.** `cursor.on_input` обрабатывает `solve`/`replay` при `DEBUG_SOLVER and action.pressed`; Space обрабатывается всегда (строки 63–71) плюс второй раз в `game_manager.on_input` без какого-либо флага. Биндинги в `game.input_binding` не завязаны на debug-вариант сборки.

### 2. Окно в один кадр: только что открывшуюся 2/цветок можно схватить, `flying_count` ещё 0 — `tableau_script.script:17–20,48–49,72,83` + `cursor.script:83–85,579–601` — серьёзно

`flying_count` поднимается только когда курсор **уже получил** `send_to_base_slot` / `send_to_flower_slot`. Tableau специально откладывает этот пост на следующий `update` (`pending_top_check`). В Defold за кадр сначала `on_input`, потом `update`. Значит, целый кадр после появления карты на верху колонки ввод ещё свободен.

Тест `A3 send_to_base_slot increments flying_count` (`test_game_scripts.lua:209–234`) зовёт обработчик курсора напрямую и не прогоняет кадр с `pending_top_check`. Его нельзя сломать этой гонкой — он её не видит.

**Как воспроизвести.**
1. Колонка: снизу `2_red`, сверху любая карта, которую можно унести (в free cell или на другую колонку).
2. Унести верхнюю. В том же `occupy`/`remove_card` слот ставит `pending_top_check = true`.
3. На **следующем** кадре, до `tableau.update`, кликнуть по `2_red`. `flying_count == 0` → драг начинается (`cursor.script:83–85`, `111–135`).
4. Дальше в том же кадре `last_card_to_slot` шлёт `send_to_base_slot` → `drop_success` на уже схваченную карту: она садится в foundation (`card.script:105–138`), `is_dragging` на карте сбрасывается, у курсора драг ещё жив.
5. Отпускание шлёт второй `drop_success`/`drop_failed`: карта выдирается из foundation или остаётся в нём визуально в другом месте. Зеркало `foundation_top` / `base_cards_count` уже успело вырасти по первому `card_to_base`.

Тот же кадр работает для цветка (`send_to_flower_slot`).

**Почему не ложная тревога.** Цепочка в коде полная: отложенный пост (`tableau_script.script:17–20, 48–49`) → инкремент только в обработчике курсора (`cursor.script:592`) → гард ввода смотрит только `flying_count` (`83–85`). Между «карта стала верхушкой» и «счётчик > 0» есть вход.

### 3. Патч `AudioContext` не глушит контекст, созданный уже без фокуса; стенд проверяет лог, а не `state` — `html5/engine_template.html:144–159`, `tools/browser-test.py:563–574` — серьёзно

Конструктор только делает `contexts.push(ctx)` и **не** вызывает `apply()`. `apply()` висит на `visibilitychange`/`blur`/`focus`. Если вкладка/iframe уже скрыты или без фокуса в момент `new AudioContext()` внутри `EngineLoader.load`, контекст не suspend-ится, пока не придёт следующее событие. Это не «звук умер навсегда», а наоборот: звук может играть в фоне.

Лог пишется **всегда** от флага `muted`, а не от того, вызвался ли `c.suspend()` / `c.resume()`:

```153:159:html5/engine_template.html
			function apply() {
				var muted = document.hidden || !document.hasFocus();
				contexts.forEach(function (c) {
					if (muted && c.state === "running") { c.suspend(); }
					else if (!muted && c.state === "suspended") { c.resume(); }
				});
				console.log("[AUDIO] " + (muted ? "suspended" : "resumed") + " ctx=" + contexts.length);
			}
```

Стенд `scenario_focus` ждёт именно эту строку после подмены `document.hidden`. Он зелёный, даже если ни один контекст не сменил `state` (уже `suspended` из-за autoplay, или `suspend()` не трогали).

Асинхронный `EngineLoader.load` сам по себе патч переживает: скрипт стоит до `dmloader.js` и до `EngineLoader.load`, `webkitAudioContext` тоже подменяется. Здесь дыры нет.

**Как воспроизвести.**
1. Открыть игру в фоне (другая вкладка) или в iframe Я.Игр без фокуса, дождаться старта движка. До первого `visibilitychange`/`blur` патч ничего не делает — звук раздачи может идти в фоне.
2. Стенд: в `apply()` оставить только `console.log` и убрать `suspend`/`resume`. `scenario_focus` всё равно получит `[AUDIO] suspended ctx=1` и `[AUDIO] resumed ctx=1`.

**Почему не ложная тревога.** В конструкторе нет `apply()` — это буквально строки 144–147. Лог не смотрит `c.state` после вызова. Тест матчит лог, не `AudioContext.state`.

## Подтвердить / опровергнуть

**(а) Авто-финиш стартует, когда жадный съём не может доиграть колонку — живо.**

`can_auto_finish` (`main.script:933–978`) требует только «каждая оставшаяся карта безопасна: `v <= min_other+1`». Порядок в колонке и «верхушка == следующая в foundation» он не смотрит. `find_next_auto_card` (`981–994`) берёт **только верхушку**, совпадающую с `foundation_top[suit]+1`.

Раздача: в колонке снизу `9_red`, сверху `10_red` (легальный стек в сделке не нужен — колонка приходит с раздачи как есть). Foundation: `red=8`, `blue=9`, `green=9`. Обе карты безопасны (`10 <= 9+1`, `9 <= 8+1`) → `can_auto_finish` true → `start_auto_finish`. Первый же `auto_finish_step` не находит ход (верхушка 10, ждать надо 9), ставит `auto_finishing=false` и возвращает ввод (`1134–1136`). Карты на месте, игрок видит короткую паузу 0.5 с и тишину. То же, если `9_red` лежит в free cell: `find_next_auto_card` ячейки не читает. Тестов на «can_auto_finish true, но ни одной верхушки не взять» в `test_game_scripts.lua` нет; F6 в `test_review_bugs.lua` проверяет только предикат безопасности.

**(б) Space / S / R в релизном пути — живо.** См. находку 1. `DEBUG_SOLVER = true` (`cursor.script:3`, `main.script:11`). Space в `game_manager` не под флагом вообще.

**(в) Гонка «схватить только что открытую карту, flying_count ещё 0» — живо.** См. находку 2. A3-тест это не ловит.

**(г) Двойной рестарт: unload + async_load без `proxy_unloaded` — живо.**

```3:13:main/Scripts/game_manager.script
local function show(self, proxy)
   if self.current_proxy then
      msg.post(self.current_proxy, "unload")
      self.current_proxy = nil
   end
   msg.post(proxy, "async_load")
end
```

`proxy_unloaded` — пустой обработчик (`39–40`). После первого RESTART/Space `current_proxy` уже `nil` до `proxy_loaded`. Второй клик по RESTART (или Space) в этом окне снова шлёт `async_load` в **тот же** `#level_proxy`, который ещё грузится/выгружается. Одиночный restart на этой версии движка, судя по стенду `census` (там жмут Space), часто проходит — unload in-memory коллекции бывает синхронным. Двойной клик и RESTART во время `async_load` — живая гонка: пустой стол, двойной `init`, ошибка прокси. Авто-сбор драконов тут ни при чём: GUI-кнопка RESTART во время полёта не глушится и бьёт в этот же `show()`.
