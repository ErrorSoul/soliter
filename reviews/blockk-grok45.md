### 2. Зависание / затяжка / замок ввода

**Уступка (хвост):**  
- цветок никогда не придёт (закопан / в ячейке) → максимум **2.0 с**, затем `end_auto_collect` → `enable_input`, при `base>=27` ещё `declare_victory` (снова `end_auto_collect`);  
- цветок садится ~0.7 с → сброс → ещё 0.3 с → порядка **~1.0 с** до победы.

**Успешный авто-сбор:** потолок `auto_collect_moves <= 24` × (~0.7 с дуга + 4 кадра) + до 3× `dragons_collected` по 1.5 с ≈ **≲ 23 с** в абсурде; на реальных досках сдвигов мало (каждый уменьшает глубину). Зависона «ввод глухой, победы нет, никто не переспрашивает» нет: цикл `give_up` → `pending_collect_retry=4` → `auto_collect_dragons` → снова `none` жив, пока `auto_collecting`.

**Кто снимает замок:**  
- `end_auto_collect` / `declare_victory` → `enable_input`;  
- исчерпание авто-финиша → свой `enable_input`;  
- `begin_auto_collect` **сам ввод не глушит** — только курсор при реальном нажатии кнопки / `auto_move_dragon`. На фазе ожидания цветка стол может оставаться кликабельным (старое поведение G4, не регрессия SETTLE).

### 4. Тесты

Пять таймерных тестов ловят заявленное:

- полёт 0.7 с без победы + пара «не вечно» → бюджет &lt; 0.7 и бесконечный wait;  
- `dt=0.008` → кадровый бюджет;  
- посадка → 0.1 с ещё не win → затем win → SETTLE=0 и «не обнулять на посадке»;  
- `auto_collect_moved` после 0.2 с → ещё 0.2 с не win → сброс на приземлении.

Шесть старых тестов не подогнаны под ложь: `auto_collect_none` в игре бывает только при `auto_collecting`, а уступка больше не мгновенная — `run_collect_frames(1.0)` приводит фикстуру к реальному пути. Без этого они проверяли бы мгновенный give_up, которого в коде больше нет.

Ограничение (не баг кода): юнит-тесты **не моделируют** отложенный `set_button_state` — всегда отвечают `none`. Они проверяют вентили времени, не интеграцию «после посадки кнопка реально зажглась и ход взяли». Сломать проводку кнопки, оставив тесты зелёными, по-прежнему можно; сломать сами вентили SETTLE/сбросов — нельзя без красного.
