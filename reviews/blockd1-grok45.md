## Находки

### 1. Асинхронный язык обновляет не все подписи — на экране бывает смесь языков  
**Где:** `gui/ui.gui_script:30–36`, `216–220`; тексты победы `183–188`; туториал `9–16`.

**Что не так.** `language_ready` вызывает `apply_language()`, а она пишет только `STATIC_LABELS` (`restart`, `tutorial`, `title`, `play`, `menu`, `skip`). Заголовок победы (`text1`: «Victory!» / «Победа!»), CTA (`text`: «PLAY AGAIN» / «ЕЩЁ РАЗ»), подсказки туториала и счётчик шагов при перекраске **не трогаются**.

**Как воспроизвести.** Любой случай, когда SDK отвечает после того, как эти строки уже нарисованы:
1. Медленный `YaGames.init` (в стенде уже заложено `YA_STUB_DELAY_MS = 20000`).
2. К этому моменту открыт туториал или экран победы (туториал за 20 с реально успеть).
3. После `language_ready`: «ПРОПУСК»/«МЕНЮ» становятся русскими, а хинт / «Victory!» / «PLAY AGAIN» остаются от `?lang=`/системы.

**Почему не ложная тревога.** Пункт 3 брифа («подписи на неправильном языке») — ровно этот класс состояний. Механизм `language_ready` как раз про поздний язык, но он чинит только часть UI. На одном victory-экране получается смесь языков (MENU уже SDK, заголовок — старый). Юнит-тесты язык UI не смотрят; `yasdk` смотрит только пиксели кнопки RESTART в рельсе — эта дыра там зелёная.

### 2. Стенд `yasdk` не проверяет конец партии и уход в меню  
**Где:** `tools/browser-test.py:943–1061`; проводка победы — `gui/ui.gui_script:166`, `game_manager.script:63–68`.

**Что не так.** Сценарий покрывает: нет SDK → PLAY до ответа → `ready,start` → фон/возврат → рестарт без второго `start` → геймплей при потере фокуса. **Нет:** победа → `stop`; MENU → `unload_level` → `stop`; PLAY AGAIN → снова `start`.

**Как воспроизвести (мысленная мутация).** Удалить `msg.post(..., "gameplay_over")` в `ui.gui_script` и оставить handler в `game_manager`: `yasdk` останется зелёным; игрок после победы висит на оверлее, а платформа считает, что партия ещё идёт, пока не нажмут MENU.

**Почему не ложная тревога.** Сейчас это ловят только юниты, и то порознь: один тест проверяет, что UI шлёт `gameplay_over`, другой — что `game_manager` на него делает `stop` (постыт сообщение вручную, без UI). End-to-end цепочки «победа → стоп в фальшивом SDK» нет. Коммит `f287129` как раз про дыру «никто не проверял» — стенд её так и не закрыл.

### 4. (ниже) После исключения в `GameplayAPI.start/stop` флаг `gameplayOn` уже выставлен — ретрая нет  
**Где:** `html5/engine_template.html:268–282`.

```javascript
gameplayOn = on;  // до вызова API
try {
  if (on) api.start(); else api.stop();
} catch (e) { mark(...); }
```

Если `start()` бросил, `gameplayOn === true`, следующее `applyGameplay` видит `on === gameplayOn` и выходит. Платформа без `start`, игра больше не пытается. На нормальном SDK маловероятно; на кривой фальшивке/обёртке — залипание. Ретрай или выставление флага только после успешного вызова были бы безопаснее.

## Что проверил и проблем не нашёл

**Порядок `LoadingAPI.ready` → `GameplayAPI.start`.** В JS `applyGameplay` не шлёт `start`, пока `readySent` ложен; `loadingReady` ставит флаг и только потом зовёт `applyGameplay`. Гонка «PLAY раньше ответа SDK» учтена; это же бьёт сценарий `yasdk` с задержкой 20 с (по коду сценария — логика верная; сам прогон не гонял).

**Парность start/stop на уровне намерений Lua.** `start_game` / `restart_level` / `switch_level` → `gameplay(true)`; `gameplay_over` / `unload_level` → `gameplay(false)`. Повторный `true` при рестарте внутри партии не дублирует `start` (JS сравнивает с `gameplayOn`). Победа шлёт `stop`, не дожидаясь MENU — в коде проводка есть.

**Владение жизненным циклом.** `game_manager` в `main.collection` вне level proxy; `ya_settled` переживает рестарт уровня; `LoadingAPI.ready` из Lua уходит один раз. `main.script` внутри прокси к SDK не ходит. Согласовано с заявленной моделью.

**Деградация без SDK.** Нет `html5` / нет `__ya` / `state=absent|failed` / нет feature — вызовы через `pcall`, игра идёт; `language_ready` не шлётся при non-ready. `/sdk.js` 404 → `YaGames` нет → `absent`. Висящий промис: Lua продолжает опрос, `ready`/`start` не уходят, геймплей локально жив.

**Фон вкладки vs звук (D2).** Gameplay только по `document.hidden`; звук ещё и по `!hasFocus`. В шаблоне D2 (`overscroll-behavior`, `touch-action: none`, `context-menu-guard`, audio-сторож) на месте, D1 их не ломает. Негативный контроль «без фокуса, но на переднем плане → всё равно start» в `yasdk` заложен.

**Язык: приоритет detect.** `yandex.lang()` → `?lang=` → система → `en`; незнакомый код платформы падает вниз. Юнит-тесты на это зелёные (перепрогнал в общем прогоне 152/152).

**Стенд `yasdk` не запускал** (нет готового HTML5-бандла в дереве). Оценка стенда — по чтению `scenario_yasdk` и сопоставлению с мостом. Песочницу Я.Игр тоже не гонял — как и автор, это открытый остаток D1.

---

**Итог:** критического «сломает модерацию / уронит игру без SDK» в прочитанном коде не видно. Самая содержательная продуктовая дыра — **неполная перекраска UI при позднем языке (смесь языков на victory/tutorial)**. Самая содержательная дыра верификации — **`yasdk` не видит победу/меню → stop**, плюс мутация неполного `language_ready`, которая зеленеет везде.
