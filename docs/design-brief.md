# Дизайн-бриф: Shenzhen Solitaire (мобильный адаптив, все экраны)

> Документ для дизайн-сессии с Claude. Самодостаточный — можно читать без доступа к коду.
> Задача: спроектировать раскладку и визуал всех экранов так, чтобы игра **нормально
> смотрелась и игралась на мобильных** (телефон в landscape), проходила модерацию Яндекс Игр.

---

## 0. TL;DR для дизайнера

- Пасьянс **Shenzhen Solitaire** (клон из Zachtronics). Web-игра (HTML5) для **Яндекс Игр**.
- **Ориентация — только landscape**, базовое поле **960×540 (16:9)**. Портрет НЕ проектируем — платформа сама просит повернуть телефон.
- Нужно: раскладки **4 экранов** (меню, игра, победа, туториал) + **визуал карты** + **UI-элементы (кнопки/оверлеи)**, адаптированные под разные пропорции телефонов.
- Стиль-ориентир: **узнаваемый минимализм оригинального Shenzhen** — плоские цвета, спокойный тёмный стол, чистая типографика. (Если предложишь 2–3 альтернативных направления — плюс.)
- Главный риск на мобилке: **тач-таргеты** (не промахнуться пальцем), **letterbox** (чёрные поля), **читаемость карт** на маленьком экране.

## 1. Что за игра (правила в двух абзацах)

Пасьянс на 40 карт: **3 масти** (red / green / black-ish «blue») × **9 значений (2–10)** = 27 обычных карт, **3 масти × 4 дракона** = 12 карт-драконов, **1 карта-цветок**.

Поле:
- **8 колонок (tableau)** — основная игровая зона. Карты кладутся стопкой, видно все. Стек: чередование мастей, убывание значения.
- **3 free cell** — свободные ячейки (по 1 карте).
- **3 foundation** — сброс по масти, по возрастанию с 2 до 9.
- **1 flower slot** — единственная карта-цветок.
- **3 dragon buttons** — собрать всех 4 драконов одной масти, когда есть свободная ячейка.

Цель — разобрать всё в foundation. Управление — **drag & drop** (на мобилке — палец).

## 2. Технические рамки движка (важно для дизайнера)

Движок — **Defold**. Есть две независимые системы координат, и это влияет на дизайн:

1. **Игровое поле (карты, слоты)** — живёт в виртуальных координатах **960×540** и **масштабируется целиком** проекцией `fixed_fit`. Карта на (200,300) всегда на (200,300); при другом соотношении сторон окна появляется **letterbox** (поля по краям). Позиции карт/слотов **не пересчитываются** под экран — только масштаб + сдвиг всего поля.
   - ⇒ Дизайн игрового поля — **фиксированная композиция 960×540**. Нельзя «подвинуть колонку под узкий экран»; можно только заложить композицию, которая хорошо переносит letterbox.
2. **GUI (кнопки, оверлеи, текст)** — отдельная система, привязка к краям **видимого** экрана через **anchors** (LEFT/RIGHT/TOP/BOTTOM) и adjust-mode (FIT / STRETCH). GUI **не уходит** в letterbox, если задать правильный якорь.
   - ⇒ Все кнопки и оверлеи задавай **относительно края экрана** (например «24px от правого-верхнего угла»), а не абсолютной точкой на поле.

**Практический вывод для макетов:** давай две «сетки» —
(A) **игровое поле** в координатах 960×540 (origin — **левый-нижний угол, Y вверх**, как в Defold);
(B) **UI-слой** — с якорями к краям экрана.

**Letterbox:** заполнять **цветом стола** (тёмно-зелёный/тёмный), не чёрным. Victory/tutorial-затемнение должно покрывать **весь экран включая letterbox** (STRETCH).

## 3. Текущая landscape-раскладка (координаты, 960×540, Y вверх)

Карта: **90×150 px**. Шаг колонок: **116 px**. Смещение карт в стопке: **−35 px по Y**.
Кнопки драконов: **48×48 px**.

```
 Y=540 ┌────────────────────────────────────────────────────────────────┐ top
       │                          [D1] y=511                             │
       │ [free1] [free2] [free3]   [D2] y=463  [flower][base3][base2][base1]
 Y≈457 │  x=80    x=193   x=309    [D3] y=416   x=541  x=657 x=773  x=889 │
       │        (D1..D3 = dragon buttons, колонка x=420)                  │
       │                                                                 │
 Y≈300 │ [t1]  [t2]  [t3]  [t4]  [t5]  [t6]  [t7]  [t8]                   │  ← 8 колонок
       │ x=77  193   309   425   541   657   773   889                   │
       │  │     │     │     │     │     │     │     │                     │
       │  ▼     ▼     ▼     ▼   стопки растут вниз (−35px/карта)           │
 Y=0   └────────────────────────────────────────────────────────────────┘ bottom
```

Точные позиции (центр слота):

| Слот | X | Y |
|---|---|---|
| free_slot 1/2/3 | 80 / 193 / 309 | 457 |
| dragon_button 1/2/3 | 420 | 511 / 463 / 416 |
| flower_slot | 541 | 457 |
| base_slot 3/2/1 (foundation) | 657 / 773 / 889 | 457 |
| tableau 1..8 | 77,193,309,425,541,657,773,889 | 299–300 |

**Наблюдения / что можно улучшить дизайном:**
- Верхний ряд плотный: free-ячейки слева, драконы-колонка посередине (x=420), цветок+foundation справа. На мелком экране мелкие цели (48px драконы) — кандидаты на укрупнение.
- 8 колонок при ширине 90px + шаг 116 занимают ~77…934 — почти всю ширину. Запаса по бокам мало ⇒ на узких экранах поле упрётся в края, боковой letterbox будет минимальным (это ок), но карты близко к краям.
- Стопки растут вниз до Y=0 — при длинных колонках нижние карты близко к нижней кромке.

## 4. Спецификация карты (визуал)

Нужен визуал карты, читаемый **и в полный размер, и уменьшенным** (на телефоне карта может рендериться ~40–60px по ширине после масштаба).

Состав колоды:
- **Числовые (2–10)** × 3 масти. Масти: `red`, `green`, `blue` (в оригинале — красный / зелёный / чёрный «bamboo/coin/character»). Нужны: крупная цифра/иероглиф + различимый символ масти.
- **Драконы** × 3 масти (red/green/white) — фигурная карта без числа, узнаваемый значок дракона.
- **Цветок** — 1 уникальная карта.
- **Рубашка** (back) — если планируется анимация раздачи/скрытых карт.

Требования к визуалу карты:
- **Различимость мастей при даунскейле** — цвет + форма символа (не только цветом, ради дальтоников и мелкого экрана).
- **Крупный индекс значения** в углу (или крупно по центру) — читается, когда видно только верхний край карты в стопке (видно ~35px верхней полосы!). **Критично:** в стопке перекрывается всё кроме верхних 35px ⇒ ключевая информация (значение + масть) должна жить в **верхних 35px карты**.
- Состояния карты: обычная, **подсветка/hint** (сейчас tint ~`(1.2,1.2,0.8)` — тёплое свечение), **drag** (приподнята), **невалидный дроп** (короткая тряска/возврат).
- Формат под атлас: спрайт-лист, id по схеме `"{value}_{suit}"` (`5_green`, `d_red`, `flower`).

## 5. Экраны (4 штуки) — что на них и где кнопки

Кнопки — на **GUI-слое**, позиционируются от края видимого экрана (якоря). Минимальный тач-таргет — **≥ 44–48 CSS-px** после масштаба (требование «нельзя промахнуться»).

### 5.1. Стартовый экран / меню
- Логотип/название игры по центру.
- Крупная кнопка **PLAY** (главный CTA, по центру).
- Опционально: выбор языка (en/ru/tr — игра локализована), кнопка правил/туториала, звук вкл/выкл.
- Фон — стол (тот же цвет, что letterbox).

### 5.2. Игровой экран (основной)
- Игровое поле из §3 (карты/слоты — на игровом слое, фикс. композиция).
- **UI-кнопки поверх**, привязка к краям:
  - **Restart** (перезапуск уровня) — угол (сейчас планировался правый-верхний).
  - **Tutorial / ?** — рядом.
  - Опционально: **звук**, **меню/домой**, счётчик/таймер (если нужен).
- Кнопки не должны перекрывать foundation/free-ячейки и не уходить в letterbox → **правый-верхний якорь**, но с учётом, что справа вверху уже foundation. Продумай, куда их деть, чтобы не мешали игре (варианты: правый-верхний над полем, или компактный тулбар).
- **Подсказка (hint)** и **auto-finish** (авто-доигрывание в foundation) — если выводить кнопкой.

### 5.3. Экран победы (Victory overlay)
- Полупрозрачное затемнение на **весь экран (включая letterbox, STRETCH)**.
- Заголовок «Victory!» / «Well done!».
- Кнопки: **Play Again / Play Now** (новый расклад) и **Menu** (в главное меню). По центру, крупные.
- Возможна праздничная анимация (частицы/карты). Кратко опиши, если предложишь.

### 5.4. Туториал (overlay поверх игры)
- Интерактивный: подсказки по шагам поверх реального мини-уровня.
- Элементы: **текст-хинт** (короткий, в свободной зоне, не перекрывает подсвеченную карту), **подсветка** нужной карты/слота, **стрелка/жест** куда тянуть, кнопка **SKIP**.
- Хинт-бокс должен переноситься на разные пропорции, не залезая на игровые объекты.

## 6. Мобильный адаптив — чек-лист для дизайна (из требований Яндекса)

Модерация Яндекс Игр проверяет это буквально:
- [ ] Элементы **не искажаются/не растягиваются** при смене размера окна (пропорции сохраняются).
- [ ] Ничего **не обрезается** и не выходит за экран при любом соотношении сторон.
- [ ] **Длинная сторона активной области ≤ 2× короткой** (16:9=1.78 — ок; учти при композиции).
- [ ] Кнопки/цели **достаточно крупные**, чтобы не промахнуться пальцем; элементы не «слипаются».
- [ ] Тексты и элементы **не перекрывают** друг друга ни в одной раскладке.
- [ ] **Letterbox** — цветом стола (не чёрный); оверлеи покрывают его.
- [ ] Полноэкранный режим; **long-tap не вызывает** системное меню/выделение.
- [ ] **Landscape-only**: на портретном телефоне Яндекс сам покажет «поверни устройство» — свою заглушку рисовать не надо (но стиль игры должен предполагать этот сценарий как норму).

**Диапазон пропорций телефонов в landscape**, которые надо пережить без обрезки/искажений:
- ~16:9 (1.78) — идеал, letterbox почти нет.
- ~19.5:9 / 20:9 (2.0–2.22) — узкие «безрамочные» → **горизонтальный letterbox по бокам** (базовое поле 16:9 уже). ⚠ близко к лимиту 2×.
- ~4:3 / 3:2 (1.33–1.5) — планшеты → **letterbox сверху/снизу**.
- **Safe-area / вырезы (notch, «остров»)**: у современных телефонов в landscape вырез слева/справа. Не клади критичные кнопки в углы под вырез — держи UI в safe-зоне (отступ ~44px от физических краёв).

## 8. Ограничения / чего НЕ делать

- **Не** проектировать портретную раскладку (только landscape).
- **Не** менять правила/логику игры — только визуал и раскладку.
- **Не** двигать игровые слоты «под конкретный экран» динамически — поле масштабируется целиком; композиция одна на 960×540.
- CSS HTML5-шаблона — можно трогать **цвет фона** за canvas, но не ломать layout движка.
